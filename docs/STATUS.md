## Where we are

**Live and fully functional end to end, with a real three-tier environment setup.** Landing page renders on Vercel Production; the registration form writes real rows to the real Neon `production` branch. PR previews and the persistent `main` "dev" deployment each get their own Neon branch automatically via the Neon-Vercel integration, isolated from production data. Local dev is pointed at the dev branch (`preview/main`), not production.

- **Fixtures without a date/time yet** (2026-10-27, branch `claude/fixtures-date-tbd-d9fc93`). The committee publishes some fixtures before they're scheduled, with blank Date/Time cells in the CricClubs export; the import used to reject them.
  - `Match.startsAt` is nullable (null = date TBD) and `Match.timeTbd` marks a known date with no start time (`startsAt` is then Atlanta midnight on that date) — migration `20261029120000_match_date_tbd`. Helpers in `lib/time.ts` (`MatchWhen`, `formatMatchWhen`, `formatCardStampOrTbd`, `compareMatchWhen`, `groupByMatchDay`).
  - Parser: blank (or "TBD"/"TBA") date → unscheduled, even if a time is given; date with blank time → time TBD; a malformed non-blank date or time is still a blocking row problem.
  - Re-import: a later file that fills in the date/time updates the same match (preview: "date/time Date TBD → Sat, Oct 24, 9:00 AM"). ## Explicitly not done yet — don't assume otherwise

- **No bot protection** for registration (Cloudflare Turnstile) — moot while the form is removed, but required before it comes back next season.
- **No approve/reject workflow.** The new admin console (see above) can only list registrations, not act on them — that plus invite issuance and the post-approval `registration.approved` email is Phase 1b.
- **No rate-limiting on the 6-digit sign-in code.** See the auth bullet above — worth fixing before this is relied on for real accounts, not just admins.
- **No player stats** — no CricClubs export of scorecards or per-series rosters has been found, so player stats have no automated source. (Results, scores and the uploaded points table are done — see above.)
- **No abuse protection on the public umpire form** (no rate limit, no Turnstile) — anyone can overwrite a fixture's umpires until an admin locks entry. Every change is in the audit log.
